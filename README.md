# Fathers.com Platform

The architecture in ten lines. Static pages are generated by
`build_pages.py`, `build_dashboards.py`, and `build_emails.py`, and deploy to
Vercel as plain HTML, CSS, and JS. Supabase carries data, auth, and the Edge
Functions in `supabase/functions/`; the browser reports, the server decides.
Row-level security scopes every participant to his own rows; all
integrity-critical writes go through functions with the service role. The
release gate is `tools/check_release.py`: determinism, claim bans on pages
and scripts, and a manifest check that fails if any referenced asset is
missing, so the repo is always the whole app. Course content imports from
`content/*.json` via `tools/import_content.py`. Doctrine lives in
`POSITIONING.md`; deferred work in `docs/DEFERRED.md`.

Build: `python3 build_pages.py && python3 build_dashboards.py`
Check: `python3 tools/check_release.py`
Functions: `supabase functions deploy checkpoint_submit progress_beat submit_award review_award`
Migrations: `supabase db push`
Content: `python3 tools/import_content.py content/<course>.json`
